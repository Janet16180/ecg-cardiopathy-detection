# Experiment 017: causal morphology templates on native CPC tokens

**Protocol frozen 24 September 2026, before GPU profiling or results.** This is a development-only screen. No calibration or test predictions are made.

## Question and fixed population

Does an explicit local squared-distance response improve an otherwise identical raw-ECG CPC classifier beyond both no branch and an ordinary convolution branch? The endpoint is a diagnostic annotation proxy. A selected template is neither a validated explanation nor a diagnosis.

Use the fixed PTB-XL pool: 15,360 full-label training recordings, the fixed nested 1,518-label subset, 1,306 development recordings, 564 calibration recordings, and 1,896 untouched test recordings. All partitions are patient disjoint. All arms receive the ordinary 20-epoch Experiment 004 CPC SSL encoder and its original train-only per-lead global mean/std normalization. Input remains native 250 Hz, twelve leads, 2,500 samples. Each five-second half is handled independently. All 79 native tokens per half are retained; no beat or chunk compression occurs.

## Three controlled arms

The **no-branch** arm is the original CNN, two-layer GRU, 512-wide mean/max pooled classifier. The **ordinary convolution** and **template distance** arms each add 32 learnable twelve-lead, 50-sample (200 ms) kernels to the same native CNN token *before* the unchanged GRU. At token index *t*, the support ends at sample *16t* within its own 1,250-sample half. Left zero padding of 49 samples makes 79 outputs including token zero. No branch accesses samples to the right of that edge or across the half boundary. The new 50-sample support exceeds the original CNN receptive field of 33 samples; the ordinary convolution arm controls for this added support and capacity.

Each bank starts from the **same** seed-42 selected label-blind windows from training recordings only. Training identifiers, half indices, and endpoint indices are recorded. The windows are transformed by the frozen train-only per-lead mean/std; there is no per-window normalization, clipping, amplitude removal, or feature selection by outcome. For window *x* and kernel *T*, the ordinary control response is `2 * <x,T> / 600`. The template response is `-||x-T||² / 600`, evaluated as `-(window_energy - 2*dot + kernel_energy) / 600` with convolution and a sliding sum. The scale 600 is the number of lead/sample elements. The corresponding dot terms have equal coefficients; the template arm additionally contains window energy and template norm. Both branches apply the same 32-to-64 linear layer, SiLU, and 64-to-256 linear layer, then add the result to CNN tokens. The final layer starts at zero so all three models initially compute the same CPC representation and classifier output. Both branch layers and the bank are trainable. There is no across-template centering that would cancel shared window energy. This formulation is algebraically related to convolution; it is not claimed as a new mathematical operator.

Both label budgets expose the same 15,360 training waveforms to every arm once per epoch. In the 1,518-label condition, only those fixed labels contribute binary cross entropy, distributed across 120 common batches so every batch has a label. The hidden training labels are never read for loss or selection. All arms use seed 42, batch 128, five epochs, AdamW weight decay 0.01, learning rate 3e-4 for pretrained CNN/GRU and 1e-3 for head and branch, gradient clipping at 1.0, and no augmentation. All six arms have 600 updates, 76,800 waveform exposures, and either 76,800 or 7,590 labeled exposures. Bank initialization and batch order are common across arms and budgets.

Select the best epoch by development AUROC among all five fixed epochs per arm. Report all epoch histories, parameter counts, and best-epoch development AUROC. A five-fold stratified patient-grouped development screen chooses a 95%-sensitivity threshold on the four other folds and reports held-out sensitivity and specificity. It is descriptive, not a calibrated threshold. A seed-42 positive screen requires template AUROC at least 0.002 above **both** ordinary convolution and no branch, and patient-fold sensitivity no more than 0.005 below convolution in at least one budget, with no more than 0.002 AUROC or 0.005 sensitivity harm versus convolution in the other. A second matched seed and artifact/template dominance checks are required before any calibration or test use. Inspect whether gains arise from signal clipping, amplitude outliers, or one template/patient; a negative screen does not establish that morphology is unhelpful.

## Execution and recovery

A CPU `check` verifies exact ECG/patient/label alignments, hashes the smaller frozen inputs, checks train-only normalization and verifies the final CPC SSL checkpoint. The full waveform pool SHA-256 values are inherited from Experiment 015's verified immutable pool receipt only after the current files' device, inode, size and nanosecond change times agree with that receipt. The 015 verifier source hash is pinned; 017 stores its own verification receipt with stable source hashes and file identity fields, retaining the exact 015 receipt SHA only as audit evidence. A bounded RAM loader copies the 15,360 training plus 1,306 development waveforms (about 2.0 GB) in source-file order and serves deterministic batches. It caps waveform RAM at 2.4 GB and leaves at least 1 GB free. The `profile` stage takes the shared V100 lock and times **one complete epoch, development pass, and checkpoint roundtrip for each of the three full-label arms**, including cold input verification and cache preload. Eleven times the three measured arm durations plus two preprocessing passes conservatively covers both profiling and all six training runs within the working two-hour planning gate. If the gate fails, no full training starts; revise the protocol in a new version rather than silently changing the frozen comparison. The `train` stage requires a matching passing real-GPU receipt, saves model, optimizer, RNG and exact batch position every 20 updates and on SIGTERM, and stops at its wall-time limit with a recoverable checkpoint.

```bash
.venv-pretrained/bin/python -m scripts.run_cpc_morphology017 --stage check --device cpu --threads 1
.venv-pretrained/bin/python -u -m scripts.run_cpc_morphology017 --stage profile --device cuda --threads 1
.venv-pretrained/bin/python -u -m scripts.run_cpc_morphology017 --stage train --device cuda --threads 1
```

Output is `outputs/experiment017_morphology_templates/`. A CPU check or runtime profile is not a performance result. The 015 pilot can finish independently; 017 may use its verified immutable input receipt after the receipt interface is frozen, with the same underlying dataset and explicit provenance.
