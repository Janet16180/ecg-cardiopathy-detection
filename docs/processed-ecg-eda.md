# EDA of the processed public ECG views

This report describes the published, read-only Challenge ECG views and the native CODE-15% part 0 output. The reproducible analysis is `scripts/eda_processed_ecg.py`; machine-readable results and a plot are in `outputs/data_quality/processed_eda/`. The post-processing does not alter `data/raw/`, the PTB-XL/MIMIC frozen experiment cohort, or any model checkpoint. These are source and signal checks, **not** clinical quality grades or performance results.

## What was processed

The Challenge strict output contains 13,686 canonical `[12,5000]` ten-second views at 500 Hz in mV from Georgia, CPSC 2018 and CPSC-Extra. The centered output contains **9,626** ten-second CPSC views selected for self-supervised use: **6,127** are crops from longer records and **3,499** come from original ten-second records. Every Challenge waveform was read from an official-checksum-verified pair, and the materializer checked its canonical hash against the audit manifest before publishing shards. The strict and centered outputs have **3,499 identical ECG IDs and canonical signals**; their union contains **19,813 unique canonical signals**, not 23,312 independent recordings. The source diagnosis codes remain unmapped to the project's PTB-XL abnormality proxy. Challenge record IDs are not verified patient IDs, so neither view is currently suitable for patient-independent supervised evaluation.

The CODE output contains 19,878 native `[4096,12]` float32 exams from **part 0 only** of the Brazilian 400 Hz release, with 19,307 real patient IDs. Native values were copied without filtering, scaling or resampling. The original 7/10-second boundary and physical amplitude unit remain unresolved, so CODE has **no canonical 500 Hz/10-second view** yet. The six released diagnosis flags and automatic `normal_ecg` flag are preserved as source metadata, not mapped endpoint labels.

## Audit outcomes and signal QC

| Source/view | Audited | Accepted | Excluded | Main exclusions |
| --- | ---: | ---: | ---: | --- |
| Georgia, strict | 10,344 | 10,187 | 157 | 52 duration, 90 exact duplicates, 9 constant leads, 6 nonfinite |
| CPSC 2018, strict | 6,877 | 2,295 | 4,582 | 4,461 duration, 107 exact duplicates, 14 constant leads |
| CPSC-Extra, strict | 3,453 | 1,204 | 2,249 | 2,050 duration, 192 exact duplicates, 7 constant leads |
| CPSC 2018 + Extra, centered | 10,330 | 9,626 | 704 | 22 short, 656 exact-view duplicates, 26 constant leads |
| CODE-15% part 0, native | 20,001 | 19,878 | 123 | 38 all-zero, 61 constant leads, 23 exact duplicates, 1 missing CSV metadata |

The strict Challenge view has **24 accepted records with QC review flags**: 21 high-amplitude flags (`>10 mV`) and 4 near-flat-lead flags (`minimum lead SD <0.01 mV`); one record has both flags. The centered view has **92 flagged records** (90 high-amplitude and 3 near-flat flags, with one overlap). Signal-amplitude summaries use all accepted Challenge manifest rows and are expressed in physical mV; the median peak absolute amplitude is about **1.65 mV** in Georgia, **2.12 mV** in CPSC 2018, and **2.09 mV** in CPSC-Extra. The CPSC maxima exceed 32 mV. A record with a constant lead is excluded rather than repaired or invented.

Inspecting **all 116 flagged view rows** found exact **+32.767 mV** samples in **2 strict rows** and **24 centered rows**, representing **24 unique source records** because the strict two also occur in the centered view. Each affected source WFDB header specifies signed 16-bit samples, gain `1000/mV`, and zero baseline, so `+32.767 mV` is exactly digital code `+32767`, the format's positive limit. These are exact rail hits; any amplitude beyond that stored limit is unavailable. The [recommended training-exclusion overlay](../outputs/data_quality/processed_eda/training_exclusion_overlay.csv) marks only those 26 view rows for downstream exclusion, with record ID, waveform hash, rail-sample count, and header hash. **Published shards and manifests remain unchanged.** The remaining high-amplitude and near-flat records stay review-only because their flags alone do not prove corruption. The [trace examples](../outputs/data_quality/processed_eda/review_examples.png) show the strict rail spikes in `cpsc_2018:A2120` and `cpsc_2018_extra:Q2427` and near-flat examples `georgia:E05473` and `cpsc_2018:A5904`.

The derived [Challenge SSL candidate manifest](../outputs/data_quality/processed_eda/challenge_ssl_curated_manifest.csv) **applies that overlay** without copying or editing arrays. It keeps strict-view rows first, then centered rows whose signal hash and ECG ID are absent from the selected strict rows. From 23,312 input view rows, it omits 26 rail-affected view rows and 3,497 remaining cross-view copies, yielding **19,789 unique ECG IDs and signal hashes**: 13,684 strict and 6,105 centered. The gross cross-view overlap is 3,499; two of those view pairs were already removed by the rail rule, explaining why the later overlap omission count is 3,497. [Every omission and reason](../outputs/data_quality/processed_eda/challenge_ssl_curated_omissions.csv) and the [hash/count receipt](../outputs/data_quality/processed_eda/challenge_ssl_curated_receipt.json) are saved. Each selected row points to an existing shard and index, carries `label_scope=ssl_only`, and has no endpoint label or patient-independent evaluation eligibility. This is a **candidate pool**, not part of the frozen experiment training set or a scheduled run. A future training consumer of the *original published views* must apply the rail overlay separately; the curated manifest has already done so.

CODE part 0 has **843 accepted review-flagged exams**, with 738 asymmetric exact-zero edge runs and 105 near-flat-lead flags in **native stored units**. The dominant exact-zero edge pairs are `(581,581)` in **11,651** exams and `(0,0)` in **7,481**; another **746** have other pairs. These counts describe stored zeros only. In particular, an odd edge pattern does not prove a bad ECG or its original duration. The unit uncertainty prevents a valid numerical amplitude comparison against the Challenge mV distributions.

## Identity, annotations, and population

In the strict Challenge audit, 389 excluded waveforms exactly duplicate an earlier accepted canonical view. **165 duplicate comparisons** have a different original diagnosis-code set, affecting **162 unique retained waveforms**; 155 are CPSC-Extra copies of CPSC 2018 signals. Of the 165 differences, 82 are subset/superset relationships and 83 are non-nested. They are annotation differences, **not adjudicated clinical contradictions**. Those 162 retained rows are marked `conflicting_duplicate_annotations` and unavailable as record annotations pending harmonization. The other **13,524** strict rows retain their original unmapped SNOMED annotation. **Zero** Challenge rows are marked eligible for the PTB-XL endpoint or for patient-independent evaluation. Centered CPSC windows are SSL-only because a record diagnosis may not apply to a ten-second crop.

CODE's accepted part 0 exams have median age **54 years**, with **3,271/19,878 (16.5%)** between ages 18 and 30. There are **553 patients with multiple accepted exams**, up to three per patient in this archive, making patient-grouped splitting essential. The six released positive flag counts range from 317 to 537 in this part; the automatic `normal_ecg` flag is positive for **7,683** exams. These are release annotations, not adjudicated PTB-XL proxy labels. They must not be used to declare a person healthy or decide a university referral.

A full semantic reread of the 19,878 accepted native CODE traces and all 123 exclusions passed, including independent QC recomputation and checks of the HDF5 rate, shape, type, and metadata contract; see [the verification receipt](../outputs/data_quality/code15_semantic_verification.json). A separate checksum-verified exact-duplicate audit found 23 excluded waveforms: 22 pairs have the same six-code diagnosis set, one pair has a retained-copy subset, four pairs disagree on the automatic `normal_ecg` flag, and **eight pairs carry different released patient IDs**. The [pair-level audit](../outputs/data_quality/code15_duplicates/code15_duplicate_annotations.csv) does not adjudicate which identifier or annotation is correct. Any future split that includes such copies must keep linked records in the same partition or exclude the ambiguous copies; the current accepted native output already excludes one copy of each exact waveform. Do not infer that distinct released IDs prove distinct people.

The [selection-bias audit](../outputs/data_quality/selection_bias.json) compares record-level retention by reported age and sex within each source. Under the strict ten-second policy, CPSC 2018 retains **19.1%** of age 18–30 records versus **42.4%** of over-70 records, and **28.7%** of female versus **37.4%** of male records. CPSC-Extra retains **15.5%** versus **37.0%** for those age groups and **29.4%** versus **39.7%** by reported sex. The centered SSL policy retains **99.1%** and **93.5%** of the corresponding CPSC age groups, though those windows remain SSL-only. Georgia strict and CODE native retention are above **98%** across the substantive age/sex groups. These are descriptive selection differences at the recording level, not evidence that age or sex causes exclusion or that the accepted samples represent a target population. The strict CPSC duration rule appears to be a major contributor and should be considered when interpreting source composition or designing a future supervised cohort.

## Reproduce and interpret

After both Challenge materialized directories and CODE native part 0 have been **fully published** (not their `.staging-*` directories), run:

```bash
MPLCONFIGDIR=/tmp/ecg_mpl .venv-pretrained/bin/python -m scripts.eda_processed_ecg \
  --strict-dir data/processed/challenge_ecg_views/strict_10s \
  --crop-dir data/processed/challenge_ecg_views/cpsc_ssl_center_crop \
  --code-dir data/processed/code15_quality/part0_native \
  --output-dir outputs/data_quality/processed_eda \
  --sample-size 128 --seed 42
```

The script checks published metadata and CSV hashes, recomputes exact cross-view overlap, validates 128 sampled Challenge shard rows per view and 128 CODE HDF5 rows against their waveform hashes, and writes [summary.json](../outputs/data_quality/processed_eda/summary.json), an [overview plot](../outputs/data_quality/processed_eda/overview.png), [review examples](../outputs/data_quality/processed_eda/review_examples.png), [all Challenge review flags](../outputs/data_quality/processed_eda/challenge_review_flags.csv), the [rail-exclusion overlay](../outputs/data_quality/processed_eda/training_exclusion_overlay.csv), and the curated SSL candidate artifacts above. It also hash-checks **every accepted Challenge record carrying a QC flag** before listing its peaks and threshold exceedances, and checks the original WFDB encoding for each rail hit. The review figure shows selected flagged leads for inspection; it is not a diagnosis. The script does **not** independently rescan every accepted waveform or infer clinical rhythm quality. Full waveform hash verification was separately completed for both Challenge outputs and CODE part 0. Challenge age/patient prevalence is not reported because verified patient identity is unavailable; source-level header ages in [the earlier raw-data assessment](data-quality-assessment.md) are descriptive only. CODE part 0 is one of 18 archives, so the numbers above must not be presented as the full release.

The next data-processing decision is to apply the rail overlay when constructing a **future training pool**, keep strict Challenge and centered SSL views separate, review the remaining flagged waveforms and conflicting original annotations, and leave CODE native until its units and padding policy are confirmed against source evidence. No new dataset is attached to the frozen experiment queue by this EDA.
